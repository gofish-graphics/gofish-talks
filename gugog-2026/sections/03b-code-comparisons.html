chart(titanicPassengers)
  .flow(
    spread({ by: "pclass", dir: "x",
      spacing: 24, alignment: "end" }),
    derive(rows => orderBy(rows,
      ["survived"], ["desc"])),
    derive(rows => chunk(rows, 14)),

The beat (this slide and the next): 1. A shared language makes it possible to compare grammars: once each grammar's idea is written in GoFish, you can put them side by side and see exactly what differs. 2. The grammars are not so different after all: they share most of their structure, and the differences come down to small, nameable pieces.

Say: Here's Atom, a grammar for unit visualizations, and its Titanic example: group passengers by class, then lay out each class's passengers as circles colored by survival. On the right is the same construction in GoFish. Every part has a counterpart. Atom's first gridxy is GoFish's first spread, by class. The second gridxy is two more spreads, rows and columns. And Atom's circle mark is GoFish's circle mark. Same idea, different name.

Honest difference (paper caption): "Atom packs units automatically; GoFish uses a fixed 14-column grid." That is the maxfill vs. chunk(rows, 14) pair. Setup (data, palette, axes) is omitted on both sides, as in the paper.

3 · The tree in practice

PiCCL lines up with GoFish

PiCCL

const scale = new PICCL.LinearScale({range: [0,400]});
const pic = new PICCL.Picture({
  url: pictureUrl, height: 400, color: "#fff"
});
const colorFill = new PICCL.Rect({
  height: 400, fill: "#00ff00"
}).mapValue("height", "amount", { scale });
const coloredPic = PICCL.atop(
  pic, colorFill, "luminosity")
  .lengthMatch(colorFill, pic, { channel: "width" });
const line = new PICCL.Line({
  x1: 0, y1: 0, x2: 250, y2: 0
}).mapValue("y", "amount", { scale });
const label = new PICCL.Text({
  fontSize: 36, fill: "#666",
  textAnchor: "end", suffix: "%"
}).mapValue("content", "amount");
const glyph = PICCL.union([coloredPic, line, label])
  .pointSnap(label, line, { anchor: [1, 0] });
const collection = PICCL.replicate(glyph)
  .stackLayout("x", 10);
await PICCL.show([[collection, data]],
  container, { pictures });

GoFish

const pic = image({ href: bottlePng, h: v(100) });
const colorFill = rect({ h: "amount", w: 175,
  fill: "#00ff00" });
const coloredPic = paint({ blendMode: "color" },
  [pic, colorFill]).name("bottle");
const line = rect({ h: 1, w: 175,
  y: "amount", fill: "#666" }).name("line");
const label = text({ text: d => `${d.amount}%`,
  fontSize: 35, fill: "#666" }).name("label");
const glyph = layer([coloredPic, line, label])
  .relate(({ bottle, line, label }) => [
    Constraint.align({ x: "start" }, [bottle, line]),
    Constraint.distribute({ dir: "y", spacing: 0 },
      [line, label]),
    Constraint.align({ x: "end" }, [label, line]),
  ]);
const collection = chart(data, { axes: false })
  .flow(spread({ by: "category", dir: "x",
    spacing: 20 }))
  .mark(glyph);

Say: PiCCL comes from graphics editors, GoFish from the grammar of graphics. Both build this bottle chart the same way: an image composited with a data-sized rectangle, a line and a percentage label snapped to it, and the glyph repeated for four categories. The matching colors and letters are the paper's (Figure 4): every part on the left has a counterpart on the right, A to F. Where do they differ? In two places, both inside those regions. First, how data-driven values are written: PiCCL's .mapValue(), GoFish's encoding channels like h: "amount". Second, how repetition is written: PiCCL's replicate plus stackLayout, GoFish's spread operator, which also groups the data by a key. That's it. Two independently designed grammars converged on the same abstractions.

The point of the two comparisons: Atom and PiCCL fit into the same tree. Written in one language, they share most of their structure, and the differences are small parts you can point to.

Lead into part 4: "So unifying grammars compresses them. But three things seem to stand in the way of that compression, and I want to take them one at a time."
