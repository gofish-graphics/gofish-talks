The claim being refuted: you have to choose between a universal grammar and a domain-specific one. McNutt's survey puts the conflict as "there is no grammar to rule them all" (quoted in the v3 draft).

Say (v3 draft's framing): "Domain grammars need words and syntax that fit their tasks. That rules out one surface interface for all visualization work. It does not rule out one language system." Here's the counterexample. On the left is GoTree, a grammar for trees, in its own JSON language. On the right is GoTree rebuilt as a library on GoFish. It keeps GoTree's tree words: a node, a link, a parent-child rule, a sibling rule. And each of GoTree's relations is a GoFish verb: within and align are align, juxtapose and flatten are distribute.

Sources: code and render are the final GUGOG paper's Figure 5 (section 3.3 "GoTree"), from examples/gotree-node-link.json, examples/gofish-gotree-node-link.ts and figures/gofish-gotree-node-link.svg, copied exactly. The paper's role letters: A node = circle, B link = line, C within = x align middle, D flatten = x distribute, E juxtapose = y distribute, F align top = y align start. Paper caption: "GoTree uses relative margins and adaptive dimensions; GoFish here uses fixed gaps." The v3 draft has its own GoTree listing (parentChild: spread(...), link: { interpolation }), but it uses an older API and has no render, so the final paper's executed figure is used here instead.

GoTree appears only here, not in the 03c code comparisons, so each example does one job.

The combine that the tree spec called turns each axis into an ordinary GoFish constraint, Constraint.align or Constraint.distribute, inside a layer(...).relate(...), the same core form from the intro slide. So GoTree keeps its own tree words, and underneath it is plain GoFish: same renderer, same constraints. The paper: "we get support for coordinate transforms, scales, and custom marks without having to design them from scratch." Domain grammars can be layered on a shared core instead of being separate languages. You get both.

Say: The same stack verb works on anything, which is the expressive part. The structure comes from the data's type: a unit declares what it can do, and stack needs values that add up. USD declared Trait.summable() stacks. Degrees Celsius doesn't have CanAdd, so the same chart is a loud error that names the missing capability, not a wrong picture.
