under the chart API is a smaller, more direct core

core · marks placed by explicit relations

const planets = enclose({ ... }, [
  spread(
    { dir: "x", alignment: "middle", ... },
    data.map((d) => circle({ r: d.r, ... }).name(d.name))
  ),
]).name("planets");

const label = text({ text: "Mercury", ... }).name("label");

layer([planets, label])
  .relate(({ mercury, planets, label }) => [
    Constraint.align({ x: "middle" }, [mercury, label]),
    Constraint.distribute({ dir: "y", ... }, [planets, label]),
    arrow({ ... }, [label, mercury]),
  ])

Target: 0:20. Running total: 3:35 of 7:00.

The code shown leaves out styling parameters (padding, fill, stroke, colors, font size, spacing) and marks each with ..., in the thesis deck's style. The live render uses the full spec in ../charts.ts.

Say: "The chart API, with spread, stack, and the rest, is built on a smaller, more direct core. Here there is no data table. The planets are four circle marks. spread puts them in a row, and enclose draws the background around them. Then we layer a label on top and relate the marks directly: the label lines up with Mercury, it sits below the background, and an arrow runs from the label to Mercury. In the core, marks are placed by explicit relations like align and distribute. The chart API is built out of these."

Why this slide is here: it gives the audience the core before the comparisons. The bottle slide two slides later mixes the chart API with these same core lines, and the hierarchy slide in part 4a can then say "the bottom row is the core you saw" instead of explaining it from scratch.
