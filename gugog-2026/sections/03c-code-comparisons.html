Grammars in one language look alike

PiCCL lines up with GoFish

PiCCL

const scale = new PICCL.LinearScale({range: [0,400]});
const pic = new PICCL.Picture({
  url: pictureUrl, height: 400, color: "#fff"
});
const colorFill = new PICCL.Rect({
  height: 400, fill: "#00ff00"
}).mapValue("height", "amount", { scale });
const coloredPic = PICCL.atop(
  pic, colorFill, "luminosity")
  .lengthMatch(colorFill, pic, { channel: "width" });
const line = new PICCL.Line({
  x1: 0, y1: 0, x2: 250, y2: 0
}).mapValue("y", "amount", { scale });
const label = new PICCL.Text({
  fontSize: 36, fill: "#666",
  textAnchor: "end", suffix: "%"
}).mapValue("content", "amount");
const glyph = PICCL.union([coloredPic, line, label])
  .pointSnap(label, line, { anchor: [1, 0] });
const collection = PICCL.replicate(glyph)
  .stackLayout("x", 10);
await PICCL.show([[collection, data]],
  container, { pictures });

GoFish

const pic = image({ href: bottlePng, h: v(100) });
const colorFill = rect({ h: "amount", w: 175,
  fill: "#00ff00" });
const coloredPic = paint({ blendMode: "color" },
  [pic, colorFill]).name("bottle");
const line = rect({ h: 1, w: 175,
  y: "amount", fill: "#666" }).name("line");
const label = text({ text: d => `${d.amount}%`,
  fontSize: 35, fill: "#666" }).name("label");
const glyph = layer([coloredPic, line, label])
  .relate(({ bottle, line, label }) => [
    Constraint.align({ x: "start" }, [bottle, line]),
    Constraint.distribute({ dir: "y", spacing: 0 },
      [line, label]),
    Constraint.align({ x: "end" }, [label, line]),
  ]);
const collection = chart(data, { axes: false })
  .flow(spread({ by: "category", dir: "x",
    spacing: 20 }))
  .mark(glyph);

The beat (this one slide): 1. A shared language makes it possible to compare grammars: once each grammar's idea is written in GoFish, you can put them side by side and see exactly what differs. 2. The grammars are not so different after all: they share most of their structure, and the differences come down to small, nameable pieces.

Say: PiCCL comes from graphics editors, GoFish from the grammar of graphics. Both build this bottle chart the same way: an image composited with a data-sized rectangle, a line and a percentage label snapped to it, and the glyph repeated for four categories. The matching colors and letters are the paper's (Figure 4): every part on the left has a counterpart on the right, A to F. Where do they differ? In two places, both inside those regions. First, how data-driven values are written: PiCCL's .mapValue(), GoFish's encoding channels like h: "amount". Second, how repetition is written: PiCCL's replicate plus stackLayout, GoFish's spread operator, which also groups the data by a key. That's it. Two independently designed grammars converged on the same abstractions. And once they're in one language, the names line up: GoFish's spread is PiCCL's stackLayout, and Atom's gridxy too.

That last sentence is the paper's section 3.4: "In Atom, spread is called gridxy with the fillX aspect ratio, while in PiCCL it's a stackLayout."

Lead into section 4: "Once grammars are written in one language, a lot of the tradeoffs we argue about stop looking forced. Two of them in particular."

Source: GUGOG camera-ready paper, Figure 4 (section 3.2 "PiCCL and Mascot"); code from examples/piccl-bottle.ts and examples/gofish-bottle.ts, image from figures/gofish-bottle-annotated.png, all copied exactly. The two differences are the paper's own words: "Where PiCCL and GoFish differ in this example is mainly in how data-driven values are described (.mapValue() vs polymorphic encoding channels) and how operators are defined (replicate and layouts vs operators that also group data by a specific key)." And: "they have independently converged on very similar abstractions."
